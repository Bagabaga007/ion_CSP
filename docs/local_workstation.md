# Local workstation readiness

scripts/ion_csp_local_check.py checks local CSP configuration for a bounded
smoke. It distinguishes CPU MLP plus CPU VASP from GPU MLP plus CPU VASP by
reading the local compute profile and the work directory config.yaml.

The check is read-only. It validates the profile, compares its gen_opt and
vasp_processing machine paths and normalized resources with the work
directory config, checks executable visibility in each stage's selected
PATH, and reads an MLP preflight receipt. Resources generated by
ion-csp-profile render are accepted when their contents match the profile.
It does not run gen_opt.mlp_python, load a model, launch VASP or MPI, connect
to another host, or modify the work directory. For a GPU MLP stage, it runs a
five-second-bounded nvidia-smi driver query.

## Prepare the profile and work directory

The profile must use mode: local, scheduler: none, a LocalContext/Shell
machine file, and both gen_opt and vasp_processing stages. The VASP stage
must be CPU. With a profile used directly, copy its absolute machine and
resources paths into the matching sections of the CSP work directory's
config.yaml. If you rendered a profile, copy the machine and resources paths
from the generated config fragment; the checker accepts the generated
resources when their normalized contents match the validated profile.

CPU MLP profiles use gen_opt.resource_class: cpu and zero GPUs in the
resources file. GPU MLP profiles use gen_opt.resource_class: gpu, exactly one
GPU per resources node, and gen_opt.nodes: 1. The one-GPU limit matches the
local GPU-selection behavior. The VASP resources file must request zero GPUs.
Set gen_opt.mlp_workers to a positive value no greater than the MLP
cpu_per_node; GPU MLP requires one worker for a bounded smoke. Each stage's
workflow node count multiplied by its allocated CPUs must fit the workstation's
reported logical CPU count.

For GPU MLP, CUDA_VISIBLE_DEVICES masks in the controller environment and
gen_opt resources must use full GPU UUIDs. If both are set, they must have at
least one UUID in common. Numeric ordinals, MIG identifiers, empty masks, and
conflicting masks fail readiness before the driver query. CPU-only MLP ignores
these GPU masks.

The check requires explicit positive values for gen_opt.num_per_group,
gen_opt.space_groups_limit, read_mlp_density.n_screen, gen_opt.nodes, and
vasp_processing.nodes. It reports the requested generation scale as
num_per_group multiplied by space_groups_limit. Missing limits are reported
as NOT RUN; project defaults are not silently substituted. The default local
limit is 100 attempts. An explicit --max-generation-attempts value can raise
the cap to at most 1,000. The documented 500 by 230 defaults exceed that cap,
so they must be reduced for a local smoke. This checker never starts the
workflow.

The local environment's PATH may be extended by the stage resources file's
approved envs.PATH. The check uses that value and the current shell PATH; run
it with the same environment or loaded modules intended for the workflow.
It checks for vasp_std and mpirun without starting them. The bundled VASP
launcher specifically invokes mpirun, so mpiexec alone is insufficient.

## Create the MLP receipt

Run the existing MLP preflight from the exact Python environment selected by
gen_opt.mlp_python, on the same local workstation. Save its JSON receipt.
For example, for the default DeepMD GPU pair:

    /absolute/path/to/mlp-python scripts/release_preflight.py \
      --target mlp \
      --backend deepmd \
      --model /absolute/path/to/model.pt \
      --require-gpu \
      --json-output /absolute/path/to/mlp-receipt.json

Omit --require-gpu for CPU-only MLP. The documented DeepMD runtime pair is
Python 3.12.x, deepmd-kit 3.2.0, and Torch 2.11.0. DPA4 profiles also use this
pair in the existing preflight contract. MatterSim uses a bring-your-own
version profile; its receipt must still pass the package, interpreter, and
model checks.

The readiness check compares the receipt target, overall result, backend,
Python version, interpreter invocation path, required package checks, model
check, and GPU confirmation when the profile requests a GPU. It hashes the
effective staged model and the model named by the receipt check, then requires
matching SHA-256 bytes. DeepMD always stages the package model; other backends
use the configured model file or the bundled file with the same basename.
Hashing reads files in chunks and refuses files larger than 512 MiB. It never
loads the model or invokes the configured interpreter. If the receipt is
missing, the result is NOT RUN and the workstation is not marked ready.

## Run the check

python scripts/ion_csp_local_check.py \
  --profile /absolute/path/to/site-profile.yaml \
  --workdir /absolute/path/to/csp-workdir \
  --mlp-receipt /absolute/path/to/mlp-receipt.json

# Optional bounded override, capped at 1,000 attempts
python scripts/ion_csp_local_check.py \
  --profile /absolute/path/to/site-profile.yaml \
  --workdir /absolute/path/to/csp-workdir \
  --mlp-receipt /absolute/path/to/mlp-receipt.json \
  --max-generation-attempts 500

The command prints credential-safe JSON. Required checks use PASS, FAIL,
or NOT RUN; the overall status is PASS only when every required check
passes. ready_for_bounded_smoke means the configuration fits the reported
small local smoke limit. It does not mean a full workload is safe or prove
MPI ABI compatibility, VASP licensing, POTCAR authorization, successful
initialization, or scientific correctness.
